# Linux port: Ubuntu dev setup, SPIR-V shaders, cross-platform tools

Goal: develop, build, run, test and debug on Ubuntu as well as Windows, without
installing anything system-wide beyond standard apt packages.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Toolchain | `tools/setup_ubuntu.sh` downloads pinned **LLVM 19.1.7**, **ninja**, **dxc** into `<repo>/.tools` (gitignored), checksum-verified. apt packages are only checked; `--install-apt` installs missing ones. | Nothing global changes on a shared machine; re-runnable; one command on a new PC. |
| Compiler | Clang 19 (same major as Windows clang-cl 19.1.5) | Same warnings on both platforms, so `-Werror` doesn't diverge. |
| Archive size | Only clang/lld/clangd/clang-format/clang-tidy + `lib/clang` are extracted from the 1.7 GB LLVM archive; the archive is deleted afterwards. | Keep `.tools` small. |
| Presets | `linux-clang` points `CMAKE_*_COMPILER` / `CMAKE_MAKE_PROGRAM` at `.tools`. Added `linux-clang-release` + a `linux-clang` test preset. | Works from a plain terminal and VS Code with no PATH changes. |
| Shaders | Hand-run `tools/compile_shaders.cmake` (`cmake -P`) emits **DXIL + SPIR-V** with dxc; both committed. Replaces `compile_shaders.ps1`. | Smallest step to Vulkan. SDL_shadercross (build-time, plus MSL for macOS) stays a later milestone. |
| Backend choice | Device offers DXIL + SPIR-V; the renderer loads the blobs matching `SDL_GetGPUShaderFormats` (`render/ShaderFormat.hpp`). | SDL tries D3D12 before Vulkan, so Windows stays on D3D12 and gains a Vulkan fallback. |
| Committed DXIL | Not regenerated by the Linux dxc. | Newer dxc gives different (untested) bytes; regenerate on Windows when a shader actually changes. |
| Normal maps | `gen_normals.ps1` ported to a C++ tool (`gen_normals`, stb), run via the `normal_maps` CMake target. | `System.Drawing` is Windows-only; the port is pixel-identical to the committed maps. |
| Debugging | `.vscode/launch.json` gains `cppdbg` + gdb entries for Linux next to the `cppvsdbg` ones. | VS Code can't switch the debugger `type` per OS inside one configuration. |
